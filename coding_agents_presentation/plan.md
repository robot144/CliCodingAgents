# Presentation Plan

## Goal

Introduce coding agents to Deltares engineers who are experienced with Python, VSCode, Linux, and numerical modelling (Delft3D-FM), but have little or no experience with AI coding assistants. The presentation should be practical and grounded — focused on what agents can concretely do for their work, not on hype.

## Audience

- Background: Python scripting, VSCode, Linux terminal, Delft3D-FM workflows, processing measurement data (netCDF4, xarray, matplotlib)
- No or minimal experience with coding agents
- Likely sceptical — need concrete examples, not abstract promises
- Privacy and safety concerns are real and should be addressed honestly

## Key messages

1. Coding agents are tools that can write, explain, debug, and refactor code — you stay in control
2. They fit into tools you already use: VSCode, the terminal
3. They are particularly useful for Python boilerplate, scripting around models, and post-processing
4. There are real limitations and risks — know them before you start
5. This repo gives you a safe sandbox to try it with Delft3D-FM already included

## Scope

- What coding agents are and how they work (brief, conceptual)
- Which agents exist and how they compare (Claude Code, Copilot, Codex, Mistral, Gemini)
- Practical use cases for this audience (Python, model runs, post-processing)
- How to get started (VSCode extension, terminal CLI)
- The containers in this repo as a ready-made on-ramp
- Honest caveats: privacy, hallucinations, safety

## Planned slides (not yet written)

- **Safety / permissions / limits** — what agents ask permission for, how to review actions, privacy considerations, the containers as a safe sandbox

## Out of scope

- Deep dives into LLM internals
- Non-Python languages
- Cloud deployment or MLOps
